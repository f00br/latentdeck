# LatentDeck Codec Package (`.ldcodec`) v2

Status: normative for the LatentDeck `0.1.x` implementation.

A Codec Package supplies one independently installable codec adapter and its
isolated worker runtime. The package format is codec-neutral: MiniMax H3 is the
first implementation, not the definition of `.ldcodec`.

The current contract uses:

- the canonical lowercase `.ldcodec` archive extension;
- `codec-pack.json` manifest version `2.0.0`;
- `integrity.json` catalog version `1.0.0`;
- Worker Protocol 2;
- an explicit, hash-bound install and activation lifecycle.

A Codec Package is not an application installer, Deck, cartridge, model, or
asset-selection record. A thin product-specific setup may install an adjacent
`.ldcodec`, but it MUST use the same package validation and lifecycle.

## Package tree

An archive contains exactly one package rooted at the ZIP root:

```text
codec-pack.json
integrity.json
<catalogued worker, adapter, runtime, notices, and metadata>
```

`codec-pack.json` and `integrity.json` are the two control files. Every other
file MUST appear in the integrity catalog. The catalog MUST NOT list either
control file. The complete physical tree must equal those two files plus the
catalog entries; an extra cache, generated bytecode file, or empty directory
invalidates the package.

The declared worker executable, runtime lock, license notice, and Python module
containing the adapter entrypoint MUST all be catalogued. The adapter module
must be importable from the worker working directory itself or its
`Lib/site-packages` directory.

## `codec-pack.json`

The manifest is a strict JSON object. Duplicate keys, unknown fields, trailing
data, non-finite numbers, and a file larger than 1 MiB are rejected.

| Field                     | Contract                                                                                        |
| ------------------------- | ----------------------------------------------------------------------------------------------- |
| `manifest_version`        | Exactly `2.0.0`.                                                                                |
| `kind`                    | Exactly `codec_pack`.                                                                           |
| `pack_id`                 | Lowercase reverse-DNS identifier. `org.latentdeck.*` is reserved for build-authorized packages. |
| `pack_version`            | Canonical lowercase SemVer and immutable storage identity.                                      |
| `display_name`, `summary` | Bounded user-facing text.                                                                       |
| `publisher`               | Name, optional HTTPS URL, and `identity_claim: self_declared`.                                  |
| `license`                 | License label and a catalogued `notice_path`.                                                   |
| `platform`                | Current closed values are `os: windows` and `arch: x86_64`.                                     |
| `compatibility`           | Host, protocol, runtime, LC, and profile requirements described below.                          |
| `adapter`                 | Adapter ID, independent adapter SemVer, and `module:callable` entrypoint.                       |
| `worker`                  | Direct executable, arguments, working directory, and start/heartbeat timeouts.                  |
| `capabilities`            | Unique closed capability names.                                                                 |
| `external_assets`         | Zero to 16 exact external asset declarations.                                                   |
| `runtime_lock`            | Catalogued dependency-inventory path and its SHA-256.                                           |
| `integrity`               | `catalog_path: integrity.json` and the catalog's SHA-256.                                       |

All SHA-256 values use exactly 64 lowercase hexadecimal characters. Package
and adapter versions are independent: changing `pack_version` does not imply a
change to `adapter.adapter_version`.

### Compatibility declaration

`compatibility` declares:

- an inclusive minimum and exclusive maximum application SemVer;
- a nonzero `worker_protocol` and `codec_adapter_api`;
- an explicit `tensor_abi` identifier;
- CPython version and Windows platform tag;
- one exact Torch build;
- one to 16 supported LC specification versions;
- one to 64 exact profile keys.

A profile key is the tuple `codec_family`, `profile`, and canonical
`profile_version`. Wildcards and `any` are forbidden. Geometry and timing are
negotiated later from the adapter's profile receipt and selected sources; a
profile key may therefore cover more than one exact signal extent.

LatentDeck `0.1.x` supports Worker Protocol `2`, Codec Adapter API `1`, tensor
ABI `latentdeck.tensor.v1`, CPython `3.13` on `win_amd64`, and LC `0.1.0`.
Compatibility is still resolved from both package manifests rather than
assuming those values for future versions.

### Worker and adapter boundary

`worker.executable` and `worker.working_directory` are package-relative normal
paths. The executable is launched directly, never through a command shell or
PATH lookup. `worker.arguments` contains at most 64 bounded strings and cannot
contain NUL, carriage-return, or newline separators. Start and heartbeat
timeouts are each within `100..=600000` milliseconds.

Protocol 2 exposes one generic codec worker. Deck packages supply their own
operators; a v2 Codec Package does not declare separate D2, Q4, or Player
entrypoints. The adapter entrypoint is an explicit portable Python
`module:callable` and is never inferred from UI state or cartridge data.

Latent tensors and decoded RGBA frames do not travel through the control
protocol. The host authenticates and supervises the isolated worker while
shared runtime resources carry bounded media data.

### Capabilities

The closed capability set is:

- `player`;
- `realtime`;
- `resample`;
- `snapshot_capture`;
- `live_capture`;
- optional `raw_import`.

The first five capabilities are mandatory for every v2 Codec Package. Missing
or duplicate capabilities make the manifest invalid. `raw_import` is optional
and only authorizes the adapter's bounded raw-to-LC preparation workflow; it
does not weaken Core validation of the resulting cartridge.

### External assets

Each external asset declaration contains:

- a unique bounded `asset_id` and display name;
- `required` state;
- one exact positive byte length and SHA-256;
- an optional HTTPS source URL;
- a license label and optional HTTPS license URL.

The declaration identifies acceptable bytes. It does not download, copy,
license, or silently select them. The user selects a regular local file, and
LatentDeck verifies its exact size and hash before runtime use. A missing
required asset produces `missing_asset`; unknown bytes fail closed.

External asset paths are machine state. They MUST NOT be stored in a package,
cartridge, preset, public diagnostic, or repository document.

## Integrity catalog

`integrity.json` has this closed shape:

```json
{
  "manifest_version": "1.0.0",
  "files": [
    {
      "path": "runtime/python.exe",
      "byte_length": 123456,
      "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
    }
  ]
}
```

Entries are unique and strictly sorted by path. Every byte length and hash must
match the archive and installed tree. The manifest binds the exact catalog
hash, while the trust receipt separately binds the archive, manifest, and
catalog identities.

## Archive and filesystem rules

| Limit                                     | `.ldcodec` value |
| ----------------------------------------- | ---------------: |
| Archive size                              |           32 GiB |
| Extracted size                            |           64 GiB |
| Total files, including both control files |           32,768 |
| Integrity-catalog payload files           |      1 to 32,766 |
| Control JSON size                         |       1 MiB each |
| External asset declarations               |               16 |

ZIP entries may use Stored or Deflate compression. Encrypted entries, links,
special filesystem objects, non-empty directory records, empty directories,
duplicate paths, case-fold collisions, and inconsistent-case path hierarchies
are rejected.

Every package path is strict UTF-8 and a bounded ASCII, forward-slash relative
path made only from normal components. Absolute, drive, device, ADS,
backslash, traversal, reserved Windows name, trailing-dot, and trailing-space
forms are rejected. Discovery and activation also reject symlinks, junctions,
and other reparse points in installed roots or referenced descendants.

The repository packer writes a deterministic Stored ZIP with sorted files,
fixed metadata, and no directory entries. It refuses an existing output,
remeasures each source while copying, and reinspects the completed archive
before atomic publication. Installers MUST accept archives produced by the
same validator rather than implementing a weaker extraction path.

## Installation and trust lifecycle

The Extensions Manager and lifecycle CLI operate only on explicit local files.
Installation requires the expected archive SHA-256, remeasures the archive,
fully validates it, extracts it into bounded staging on the same base volume,
validates the extracted tree again, and atomically publishes the version. A
trust receipt is written only after the package tree is complete.

Current-user storage is fixed:

```text
%LOCALAPPDATA%\LatentDeck\CodecPacks\<pack_id>\<pack_version>
%LOCALAPPDATA%\LatentDeck\PackageTrust\codecs\<pack_id>\<pack_version>.json
```

An installed version is initially disabled. Up to 256 package IDs and 16
side-by-side versions of one ID are allowed. Installed bytes are immutable:
install never overwrites or silently repairs an existing version. Exactly one
version of a given Codec Package ID may be enabled at a time, and the user must
select it explicitly when multiple versions exist. There is no newest-version
fallback, inherited trust, URL install, or automatic update.

The receipt records the exact package identity, archive hash and length,
manifest hash, catalog hash, self-declared publisher name, installation time,
and enabled state. An optional runtime seal can avoid repeating a full hash of
an unchanged large Codec Package on every launch; it is hash-bound cache data,
not a replacement for the receipt, closed-tree checks, retained file handles,
or the runtime usage lease.

Lifecycle operations have these semantics:

- `inspect` validates an archive without installing it;
- `pack` creates and reinspects a deterministic archive without clobbering;
- `install` publishes one new exact version, disabled;
- `verify` revalidates the complete installed tree and receipt;
- `enable` and `disable` update one exact version atomically;
- `repair` restores one disabled exact identity from a matching archive;
- `remove` removes one disabled, unused exact version; corrupt removal requires
  an explicit override;
- `list` isolates individual corrupt or untrusted candidates instead of hiding
  healthy packages;
- `matrix` reports every installed Deck-version by Codec-version pair.

An active runtime keeps a shared usage lease and retained handles for its exact
validated tree. Disabling affects future launches; it does not invalidate an
already running session. Removal and repair fail while the exact package is in
use.

Package IDs under `org.latentdeck.*` require a build-generated bundled index
that binds the exact kind, ID, version, and archive hash. External publishers
MUST use their own reverse-DNS namespace. An expected SHA-256 proves which
bytes were approved; `publisher.identity_claim: self_declared` is not publisher
authentication.

## Compatibility and failure behavior

Package compatibility is an exact intersection of application range, Worker
Protocol, host and adapter APIs, tensor ABI, Python/Torch runtime, LC version,
profile keys, and required capabilities. Selected-source compatibility then
adds external asset presence, selected device, exact signal geometry, decoded
dimensions, timing, and source count.

An incompatibility is visible and stable. LatentDeck does not silently fall
back to Worker Protocol 1, another Codec Package, another profile, CPU, a
different model, or hidden cast/resize/crop/re-encode behavior.

## H3 reference implementation

The current H3 package uses pack and adapter version `0.2.0`, Protocol 2,
CPython 3.13, an exact CUDA Torch build, the
`minimax_h3 / h3_av_latent / 0.1.0` profile, all five mandatory capabilities,
and optional `raw_import`. Its TAEH3 decoder is a required external asset and
is never embedded in the package.
