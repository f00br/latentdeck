# Support

Choose the channel that matches the request. This keeps reproducible defects,
research discussion, and private security reports separate.

## GitHub Discussions

Use Discussions for:

- installation and workflow questions;
- Q&A about cartridges, operators, Decks, codecs, or the SDKs;
- research observations and experiment design;
- show-and-tell and links to independent community extensions;
- broad ideas that are not yet a scoped change.

Search existing discussions and the [documentation hub](docs/README.md) first.
Include product and extension versions, but do not post private media, model
assets, credentials, or machine-local paths.

## GitHub Issues

Use an Issue for:

- a reproducible defect;
- incorrect or missing documentation;
- a scoped extension proposal;
- a research direction with an explicit baseline and observable outcome.

Use the provided form. Keep one problem per Issue and reproduce it with
synthetic or redistributable material whenever possible. Stable error codes,
sanitized logs, and a reviewed diagnostic bundle are more useful than a screen
recording of a generic failure.

The [diagnostics guide](docs/repository/DIAGNOSTICS.md) explains what a support
bundle contains and excludes. Inspect any bundle before attaching it.

## Security and conduct

Do not report a vulnerability in a public Issue. Follow [SECURITY.md](SECURITY.md)
for the current private reporting route: GitHub Private Vulnerability Reporting
when visible, or the documented secure-channel fallback before it is enabled.

For a private Code of Conduct report, message `@wde` on Discord. Do not post the
incident publicly or contact the subject of a report on behalf of the project.

## Unsupported requests

The project cannot provide model weights, proprietary cartridges, private
datasets, or licenses for third-party assets. Preview support covers the
documented Windows/H3 path and public extension contracts; custom builds,
forks, and unmeasured hardware combinations are best-effort community topics.
